# Sony VENICE / FX6 / FX3 机内监看 LUT 技术规范与 S-Log3 调色指南

本参考手册用于辅助排查从 DaVinci Resolve 导出的 `.cube` 3D LUT 在 **Sony VENICE（威尼斯 1/2 代）、FX6、FX3** 等 Sony CineAlta / Cinema Line 机型上加载时出现的条纹（类似斑马纹）、极暗部噪点与加载报错问题。

---

## 1. Sony 摄影机机内 3D LUT 硬性规格要求

| 检查项 | Sony VENICE / VENICE 2 / FX6 / FX3 要求 | 常见踩坑表现 |
| :--- | :--- | :--- |
| **晶格尺寸 (`LUT_3D_SIZE`)** | **必须为 `33`**（部分老固件或 Atomos 支持 `17`，但官方标准机内 3D LUT 为 **33 点**） | 达芬奇默认或手动选了 `65 Point Cube`，导致摄影机无法导入、拒绝加载或截断失效。 |
| **LUT 类型** | **仅支持纯净单一 3D LUT**（无 `LUT_1D_SIZE`） | 含 `LUT_1D_SIZE` 的 1D+3D Shaper 复合 `.cube` 在部分机内固件中会被忽略 1D Shaper 或直接报格式错误。 |
| **输入值域 (`DOMAIN_MIN` / `MAX`)** | 必须为 **`0.0 0.0 0.0` 到 `1.0 1.0 1.0`** | 若带非标准 Domain（如 `-0.1` 到 `1.5`），机内硬件往往按 `[0, 1]` 映射，导致整条曲线错位、黑灰发闷或高光过早溢出。 |
| **输出数值安全范围** | 建议严格限制在 **`[0.0, 1.0]`**，严禁 `NaN` / `Inf` | 摄影机机内 FPGA/ASIC 监看管线多为**定点（Fixed-Point）或无符号整数映射**，浮点 `< 0.0` 或 `> 1.0` 越界极易触发**整数溢出回绕（Wrap-around）**。 |
| **文件编码与命名** | 纯 **ASCII / 无 BOM UTF-8**，`TITLE` 仅用英文数字与下划线，文件名避免中文与特殊空格 | 带 UTF-8 BOM（`\xef\xbb\xbf`）或中文 `TITLE` 可能导致相机读卡识别失败或乱码。 |
| **机内插值方式** | 硬件 FPGA 常用 **Trilinear（三线性插值）** | DaVinci Resolve 内部默认使用 **Tetrahedral（四面体插值）**，高扭曲 DCTL 在降采样到 33 点且改用三线性插值后，局部斜率或色相会出现肉眼可见的条纹与色阶断层。 |

## 2. 为什么机器上会出现“类似斑马纹的工具”？

在机内套用 LUT 后，高光或高饱和度渐变区域出现一条条黑白交替、彩色条带或等高线状条纹，核心机制有四类：

1. **输出超界 `> 1.0` 引发机内定点溢出回绕（最典型）**
   - DaVinci Resolve 默认工作在 32-bit float，很多 DCTL（如胶片模拟、高光滚降、锐化/对比度插件）会在高光或极高饱和边缘输出 `1.01 ~ 1.25` 的浮点超白值。
   - Resolve 里视口会自然裁切显示为纯白，因此调色师**完全看不出异常**；但导入摄影机定点监看硬件后，`1.02` 经过无符号定点编码回绕成 `0.02`（纯黑），于是高光亮部边缘会周期性地陷落成黑色条带，视觉上极像斑马纹。
2. **过激色度变换导致单调性反转（Solarization / Non-monotonicity）**
   - 当输入的亮度或某通道递增时，LUT 输出的亮度 $Y = 0.2126R + 0.7152G + 0.0722B$ 反而突然下降（$\partial Y / \partial x < 0$），在平滑渐变天空或人脸高光过渡带就会形成一道“亮-暗-亮”的反相条带。
3. **DCTL 内置指示层或硬阈值分支未关闭**
   - 导出 LUT 前忘记关闭 DCTL 插件中的 Zebra、False Color、Gamut Warning 或硬边界 `if (val > th)` 分支（未使用 `smoothstep`），导致 LUT 晶格被写入阶跃断层或周期波纹。
4. **3D 晶格空间折叠（Jacobian Determinant $\det(J) < 0$）与插值分歧**
   - 过度的 Tetrahedral HSL 扭曲或减法饱和度 DCTL 会令 3D 立方体体素自相交叉翻转；在达芬奇四面体插值下勉强平滑，到相机三线性插值下则裂解为条纹带。

## 3. S-Log3 黑电平锚点与“极暗部噪点”的数学共振机制

Sony VENICE / FX6 / FX3 的标准 S-Log3 编码（基于 10-bit Data Range `0 ~ 1023` 映射到 `[0.0, 1.0]`）关键锚点如下：

| 物理意义 | 反射率 | 10-bit 码值 (0-1023) | 归一化输入 ($0.0 \sim 1.0$) | 33 点晶格位置 ($i / 32$) |
| :--- | :--- | :--- | :--- | :--- |
| **Sub-Black（超黑/热噪区）** | `< 0%` | `< 95` | `< 0.092864` | 晶格 `0, 1, 2` (`0.000, 0.03125, 0.06250`) |
| **0% Black（黑电平）** | `0%` | **`95`** | **`0.092864`** | **紧贴晶格 `3` (`3/32 = 0.09375`)** |
| **暗部阴影关键带** | `~2% - 5%` | `140 - 220` | `0.137 - 0.215` | 晶格 `4 ~ 7` |
| **18% 中灰 (Mid Gray)** | `18%` | **`420`** | **`0.410557`** | 晶格 `13` (`0.40625`) |
| **90% 白 (White)** | `90%` | **`598`** | **`0.584555`** | 晶格 `19` (`0.59375`) |

> [!IMPORTANT]
> **为什么极暗部噪点总是在 S-Log3 机内监看中爆发？**
> 1. 传感器暗电流与读取噪点在 S-Log3 下以 **`0.092864`（码值 95）为中心上下波动（约 ±0.003 ~ ±0.008）**，刚好跨越 33 点 LUT 的**第 2 层（`0.0625`）、第 3 层（`0.09375`）和第 4 层（`0.125`）**。
> 2. 如果 DCTL 中存在线性光下暗部增益过大、对数斜率在 `95` 附近突然抬高（如过度拉低暗部 Lift 之后再做强 Contrast，或 S-Log3 解码后出现微弱负值再被饱和度公式 `chroma / max(L, eps)` 除零放大），第 2~4 层近中性灰邻域晶格就会出现强烈的**R/G/B 通道分裂**或**局部超高斜率**。
> 3. 原本肉眼几乎不可见的 10-bit ±2~3 码值传感器底噪，经过该晶格区间后会被放大 **5~20 倍**，在 VENICE / FX6 / FX3 的暗部画面上呈现为闪烁的彩色杂点或块状粗噪点。
> 4. 若晶格 `0~3` 层输出了 `< 0.0` 的微小负值（例如 `-0.004`），机内无符号硬件回绕后会直接变成 `0.996`（纯白/高饱和亮点噪点）！

## 4. DaVinci Resolve 导出 Sony 机内 LUT 的标准检查清单

在 DaVinci Resolve 中准备导出给 **VENICE / FX6 / FX3** 的 `.cube` 时，请务必确认：

1. **Project Settings -> Color Management**：
   - 使用 **DaVinci YRGB**（非 ACEScct 除非明确首尾都在相同空间，推荐 Timeline 为 `S-Gamut3.Cine / Sony S-Log3`）。
   - 如果使用 **DaVinci YRGB Color Managed**，务必理解 Resolve 导出 LUT 只会烘焙当前 **Timeline 节点树** 的变换（不包含自动 Input/Output Color Space Transform），建议关闭 RCM 而是在节点树首尾显式放置 `CST (S-Log3 -> Timeline)` 与 `CST (Timeline -> Rec.709)`，或在 S-Log3 空间直接做节点调色后再转 Rec.709。
2. **禁止导出空间型 / 时间型特效**：
   - LUT 只能记录逐像素 3D 颜色映射！导出前必须**关闭或绕过**以下节点：胶片颗粒（Film Grain）、光晕（Halation）、柔光/辉光（Glow/Mist）、锐化/降噪（NR/Sharpen）、暗角（Vignette）、任何基于邻域像素卷积的 OFX。
3. **检查 DCTL 插件面板开关**：
   - 确认所有 DCTL 上的 `Show False Color`、`Gamut Warning`、`Zebra`、`Clip Highlight`、`Split Screen` 均已关闭。
4. **导出格式与 Levels 设定**：
   - 右键时间线缩略图 -> `Generate LUT` -> 选择 **`33 Point Cube`**。
   - **Data Levels / Video Levels 一致性**：
     - Sony VENICE / FX6 / FX3 机内 User 3D LUT 默认按 **Full/Data Range (`0.0 - 1.0`) 对应 S-Log3 原始数据** 解算。若 Resolve 输出时误选 `Video Levels (64-940)` 压缩并导出 LUT，或源素材 Clip Attributes 设错，会导致黑电平错位（`0.0928` 被误映射到 `0.062` 或 `0.15`），引发严重发灰或死黑彩噪。
     - 建议在 Resolve 内始终以 **Full/Data** 流程处理 S-Log3（或确认项目设置中对 Sony XAVC / X-OCN 保持自动匹配且 LUT 导出映射完整覆盖 `[0.0, 1.0]`）。
